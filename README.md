## Анализ существующего решения
### Бэкенд
1. В проекте присутствую 2 контроллера: `users` и `cards`. Первый отвечает за работу с пользователем. Второй - за работу с фотографиями.
2. Существуют 2 модели данных: `card` и `user`.
3. Роуты прописаны в соответствии со стандартами `REST`.
    - Фотографии:
        - Используется контроллер `cards`
        - Получение списка фотографий: `/cards/` [GET]
        - Добавление фотографии: `/cards/` [POST]
        - Удаление фотографии: `/cards/{id}` [DELETE]
        - Добавление лайка: `/cards/{id}/likes` [PUT]
        - Удаление лайка: `/cards/{id}/likes` [DELETE]
    - Пользователи:
        - Используется контроллер `users`
        - Получение списка пользователей: `/users/` [GET]
        - Получение информации о пользователе: `/users/{id}` [GET]
        - Изменение информации о текущем пользователе: `/users/me` [PATCH]
        - Изменение изображения профиля текущего пользователя: `/users/me/avatar` [PATCH]
    - Регистрация пользователя: `/signup` [POST]
    - Авторизация пользователя: `/signin` [POST]

### Фронт
- Реализован на React
- Стили разбиты по отдельным типам блоков. Есть пересекающиеся стили (всплывающие окна), которые в зависимости от требований могут быть как частью отдельных микрофронтендов (если необходима унификация), так и общими.
- В проекте присутствуют шрифты и нормализация, которые следует сделать общими для всех микрофронтендов.

## Потенциальные проблемы
- Выдача фотографий происходит без привязки к пользователю или учета системы рекомендаций. Просто выдаются все фотографии. По сути, это одна общая лента для всех пользователей.
- Нет пагинации при выдаче изображений.
- Нет возможности просмотреть "мои" фотографии.
- Невозможно масштабировать отдельные части бэкенда независимо от других. 
- Основная нагрузка будет приходиться на отображение карточек. Желательно иметь возможность горизонтального масштабирования этого сервиса независимо от других.

## Предлагаемое решение
- Разбить бэкенд на микросервисы
    - Авторизация
    - Информация о пользователе
    - Изображения
    - Поиск и рекомендации
- Разделить фронтенд на следующие микрофронтенды:
    - Авторизация (регистрация пользователя, авторизация, аунтентификация)
    - Профиль (CRUD-операции для пользователя)
    - Карточки (CRUD-операции для фотографий)
    - Взаимодействие между фронтендами реализовать по event-driven принципу.
